### 2026-08-30 · decision · dark mode
- Light + dark, both shipped with MVP. Token-driven swap. Manual user toggle in settings.

### 2026-08-30 · decision · notifications (recurring reminders)
- In-app only for MVP. Surfaces as a prominent banner/due list when the app opens. No Web Push, no background sync — matches PRD's reminder model (no background job required).

### 2026-08-30 · decision · onboarding
- 3–4 step wizard after signup: (1) welcome, (2) create first account, (3) optional first budget, (4) 'add your first expense' CTA. Goal: user records one real expense in <2 minutes.

### 2026-08-30 · decision · form-factor
- Mobile-first PWA, with desktop-responsive layouts in the same codebase (no separate desktop IA).
- Navigation pattern TBD; likely bottom-tab on mobile, sidebar/top-nav on desktop.

### 2026-08-30 · decision · offline behavior (PRD §9 deferred)
- Online-only for MVP. PWA installable (manifest + service worker for shell), but reads/writes require connectivity.
- No offline cache for expense data, no write queue, no sync state. Out of scope: anything beyond service-worker shell.

### 2026-08-30 · decision · accessibility target
- WCAG 2.1 AA — consumer-grade. No formal external audit at MVP, but patterns comply (contrast, touch targets, semantic structure, keyboard, focus states, screen-reader labels).

### 2026-08-30 · decision · motion
- Tasteful, functional. Subtle transitions on confirm/save, soft chart-load animation, list enter/exit. Always honors `prefers-reduced-motion: reduce`.

### 2026-08-30 · decision · i18n / locale
- Single locale for MVP: English UI + BDT currency symbol (৳). No i18n framework. Currency hardcoded per PRD.

### 2026-08-30 · decision · input modalities — quick-add expense
- Numeric keypad appears by default (amount first), then category, then account, then description. Optimizes for 'record quickly' — the PRD's stated goal.

### 2026-08-30 · decision · dashboard primary view
- Monthly snapshot first: this-month total spent, top 3 categories vs budget (bar/progress), savings goal progress. Each card drillable into the full Reports view. Recent expenses below as a secondary list.

### 2026-08-30 · decision · stakes
- Consumer. Handles personal financial data, but not a regulated financial product (no bank, no lending, no fiduciary duty, no PCI scope). Drives accessibility target (AA consumer) and copy tone (helpful, never advisory).

### 2026-08-30 · decision · navigation IA
- 5-tab bottom nav on mobile: **Home** · **Expenses** · **Budgets** · **Reports** · **More**.
- **More** holds: Accounts, Categories, Recurring Expenses, Savings Goals, Settings (profile, theme, sign out).
- Desktop (responsive ≥1024px): same items reflow as left sidebar; primary content on the right. Top app bar carries search + user menu.

### 2026-08-30 · decision · recurring due reminder surface
- Dismissible banner at top of Home when at least one recurring template is due (one-tap 'Review' → confirm flow).
- Companion: red dot on the More tab while any due template is unread.
- No push, no full-screen takeover.

### 2026-08-30 · decision · expense list default
- Grouped by day, newest day first (sticky day headers: Today / Yesterday / explicit date). Tap row → edit. Long-press → action sheet (edit, delete, duplicate).

### 2026-08-30 · decision · category picker UX
- Tappable horizontal scroller of category icons + names, most-used first, with a search field above for users with many custom categories. Scroll-snap.

### 2026-08-30 · decision · edit recurring template
- Editing a template affects future occurrences only. Past confirmed expenses remain unchanged (they're independent rows in `expenses`). Documented clearly in the edit-recurring UI.

### 2026-08-30 · decision · budget overage behavior
- Non-blocking warning chip on the Add Expense screen when the new expense pushes the chosen category over budget ('This puts Transport at 105% of budget'). User can still save.

### 2026-08-30 · decision · auth flow (Supabase Auth)
- Email + password sign-up with confirmation email; sign-in; forgot-password → reset email. No social providers at MVP. No magic-link-only.

### 2026-08-30 · decision · delete account with linked expenses
- Confirm cascade-delete: 'Deleting this account will also delete N linked expenses. Continue?' Type-account-name to confirm if destructive (TBD at Finalize — simple confirm is acceptable for MVP). User accepts the loss explicitly.

### 2026-08-30 · decision · empty states
- Every empty screen = small illustration + one-line helpful copy + primary CTA. Examples: empty Expenses list → 'No expenses yet. Tap + to add your first one.'

### 2026-08-30 · decision · error / loading patterns
- Form errors: inline next to the field. Page-level errors: top banner with retry. Loading: skeletons for lists, spinners only for in-flight actions.

### 2026-08-30 · decision · PWA install prompt timing
- Show after the user has logged their first expense (value proven). Suppressible ('Not now' dismisses for the session). Manual install path always available in Settings.
