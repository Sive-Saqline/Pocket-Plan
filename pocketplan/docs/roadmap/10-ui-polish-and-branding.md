# Step 10: UI polish & branding

**Status:** 🟡 Partially done (paused 2026-11-13; next: Step 22) · **Depends on:** nothing (first remaining step)

**Also done in this step:** responsive desktop/tablet layout with a sidebar (bug B4), profile photo upload, web app pinned to port 3000.
**Still open:** visual check of Register, the Recurring screens and desktop width; a full `npm run build`; moving the older buttons onto the shared `Button`.

## Goal
Give PocketPlan a consistent, professional look **before** new screens are built, so Steps 11–21 use the same icons, logo, and components from the start. This step changes only how things look, never what they do.

## Tasks
1. **Remove emojis (about 40 lines across the web app and the default categories).**
   - Pick one icon library (recommended: `lucide-react`) and create a single `<Icon name="..."/>` component.
   - Category icons: store an icon **key** (e.g. `"food"`) instead of an emoji. Map old emoji values to keys so existing saved data still shows correctly.
   - Replace emojis in navigation, buttons, banners, empty states, and the More menu.
2. **Logo and brand.**
   - Create the PocketPlan logo as SVG: a symbol and a "PocketPlan" wordmark, with light and dark versions.
   - Use it in the app header, Sign In and Register, and the browser tab icon.
   - Export app icons now (192, 512, maskable, Apple touch). They're needed in Step 20.
3. **Visual consistency.**
   - One set of colour, spacing, corner-radius, and font tokens in `globals.css`; remove one-off values.
   - Shared components for buttons, inputs, cards, sheets, empty states, and loading skeletons, used everywhere.
   - Amounts in ৳ use the same format and alignment on every screen.
4. **Accessibility.** Contrast meets WCAG AA in both themes; every icon-only button has a label; keyboard focus is always visible; tap targets are at least 44px.
5. Write a short **UI guide** (`docs/ui-guide.md`) covering icons, colours, and components, for later steps to follow.

## Out of scope
New screens or features. Any change in behaviour.

## What was done (2026-11-13)

- **Icons:** `lucide-react` added. About 40 emoji and symbol uses (⚠ ● × ‹ › → ✓ and the like) replaced. Category and wallet icons go through `components/ui/icons.tsx`.
- **Category icon keys:** new accounts get keys (`food`, `transport`, ...) from `apps/api/src/ledger/defaults.ts`. Existing accounts with emoji icons still display correctly (checked with emoji data).
- **Logo:** pocket-with-check mark plus a "PocketPlan" wordmark (`components/brand/Logo.tsx`), shown in the app header and on Sign In/Register. Browser tab icon `src/app/icon.svg`. Apple icon and app icons (192, 512, maskable) are generated by `apps/web/scripts/generate-icons.mjs`. The default Next.js `favicon.ico` was removed.
- **Shared components:** `Button`, `EmptyState`, `CloseButton` added. All sheets use `CloseButton`, all empty states use `EmptyState`, and the duplicate `group/Card.tsx` was removed. Some older buttons (sheet Save buttons, Sign In, Profile) still use their own matching classes; switch them to `Button` when those screens are next touched.
- **Accessibility:** contrast of the key colour pairs checked (all ≥ 4.5:1 in both themes); filter chips raised to 44px; focus outlines added to icon buttons.
- **UI guide:** [docs/ui-guide.md](../ui-guide.md).
- **Not changed:** behaviour, except bug B1 (the "can't reach the server" screen).

## Notes
- `apps/web/.next` is shared by every Next.js process in that folder. Running a second dev server or `npm run build` while your dev server is running makes them overwrite each other's build. Stop your dev server before running `npm run build`.
